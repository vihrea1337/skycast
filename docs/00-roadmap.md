# 00 — Роадмап проекта

Каждый этап заканчивается **работающим приложением** (пусть и урезанным) и отдельным git-тегом (`v0.1`, `v0.2`, ...). Оценки времени — из расчёта «вечерами», по 1.5–2 часа.

## Этап 0 — Фундамент (~2–3 вечера)

- [ ] `git init` в корне папки, первый коммит с `docs/`, репозиторий на GitHub (public)
- [ ] Создать проект в Android Studio: шаблон **Empty Activity (Compose)**, package `com.<ник>.skycast`, minSdk 26, Kotlin DSL
- [ ] Перевести зависимости на version catalog `gradle/libs.versions.toml` (обычно уже так)
- [ ] Подключить detekt + ktlint (см. `31-ci-cd.md`), исправить замечания
- [ ] Базовый CI на GitHub Actions: build + detekt + unit tests на каждый push/PR
- [ ] `.gitignore`, `LICENSE` (MIT)

**Готово, когда:** пустое приложение собирается локально и в CI, бейдж CI зелёный.

## Этап 1 — Каркас: модули, DI, навигация, тема (~3–4 вечера)

- [ ] Разбить на модули: `:app`, `:core:common`, `:core:model`, `:core:designsystem`, `:feature:home` (пустой экран) — остальные добавлять по мере надобности
- [ ] Convention plugins в `build-logic/` — опционально; для старта достаточно аккуратных build.gradle.kts
- [ ] Hilt: `@HiltAndroidApp`, `@AndroidEntryPoint`, первый `@HiltViewModel`
- [ ] Navigation Compose с type-safe маршрутами (`@Serializable` routes), NavHost в `:app`
- [ ] Тема Material 3: светлая/тёмная, dynamic color (Android 12+), edge-to-edge, Splash Screen API

**Готово, когда:** приложение открывает пустой Home-экран через NavHost, тема переключается с системной.

## Этап 2 — Сеть и первая погода (~4–5 вечеров)

- [ ] Изучить Open-Meteo в Swagger Editor, зафиксировать нужные поля (см. `03-api-swagger.md`)
- [ ] Написать свою урезанную `openapi/weather-api.yaml`
- [ ] `:core:network`: Retrofit + OkHttp + kotlinx.serialization, DTO, `safeApiCall`
- [ ] `:core:data`: `WeatherRepository` (пока без кэша — напрямую из сети)
- [ ] Home-экран показывает текущую погоду для захардкоженного города (Сургут: 61.25, 73.39): температура, иконка по WMO-коду, ветер, влажность
- [ ] Состояния Loading / Success / Error на экране

**Готово, когда:** реальная погода видна на экране, при выключенном интернете — внятная ошибка с кнопкой Retry.

## Этап 3 — Offline-first: Room (~3–4 вечера)

- [ ] `:core:database`: entities + DAO (current, hourly, daily, locations), Flow из DAO
- [ ] Репозиторий переводится на паттерн «БД — единственный источник правды»: UI читает только из Room, сеть лишь обновляет БД
- [ ] Политика устаревания: авто-refresh при открытии, если данным > 30 минут; таймстамп «обновлено N мин назад» в UI
- [ ] Pull-to-refresh

**Готово, когда:** в авиарежиме приложение показывает последние данные с пометкой времени обновления.

## Этап 4 — Города и настройки (~4–5 вечеров)

- [ ] `:feature:search`: поиск города через geocoding API (debounce 300 мс), список сохранённых городов, выбор активного
- [ ] Геолокация: FusedLocationProvider + запрос разрешения `ACCESS_COARSE_LOCATION`, graceful fallback на поиск
- [ ] `:core:datastore` + `:feature:settings`: единицы температуры (°C/°F), ветра (м/с / км/ч), тема (системная/светлая/тёмная)
- [ ] Первый запуск: онбординг-заглушка «выбери город или дай геолокацию»

**Готово, когда:** можно жить с приложением: свой город, свои единицы, всё переживает перезапуск.

## Этап 5 — Полный прогноз и полировка UI (~3–4 вечера)

- [ ] Home: почасовой прогноз (LazyRow, 24 ч) и прогноз на 7 дней (min/max, иконки, восход/закат)
- [ ] Скелетоны при загрузке, анимации, форматирование дат/чисел по локали
- [ ] `:core:domain`: вынести логику в use cases (см. `17-module-core-domain.md`)

**Готово, когда:** экран не стыдно поместить на скриншот в README.

## Этап 6 — Виджет (~3–4 вечера)

- [ ] `:widget` на Glance: компактный вариант (город, t°, иконка) и средний (+ прогноз)
- [ ] Обновление через WorkManager (Periodic, 30 мин) + мгновенно после sync в приложении
- [ ] Клик по виджету открывает приложение; состояние «нет данных»

**Готово, когда:** виджет живёт на домашнем экране сутки и не показывает вчерашнюю погоду.

## Этап 7 — Тесты (~4–5 вечеров, частично параллельно с 3–6)

- [ ] Unit: мапперы, репозитории (MockWebServer + in-memory Room), use cases, ViewModel'ы (Turbine)
- [ ] Smoke UI-тест: приложение открывается, Home показывает данные с fake-репозиторием
- [ ] Тесты в CI обязательны

**Готово, когда:** падение любого маппера/репозитория ловится тестом, CI красный при поломке.

## Этап 8 — Портфолио-финиш (~2–3 вечера)

- [ ] README по шаблону из `32-portfolio.md`: скриншоты, GIF, диаграмма архитектуры, бейджи
- [ ] Release-сборка с R8/minify, проверка на реальном устройстве
- [ ] Тег `v1.0`, GitHub Release с APK

## Этап 9 (опциональный, stretch goal) — свой бэкенд со Swagger UI

Мини-прокси на Ktor: агрегирует Open-Meteo, отдаёт свой JSON, документирован через OpenAPI + Swagger UI. Детали в `03-api-swagger.md`. Делать только после `v1.0`.

---

### Правила по ходу всего проекта

- Коммиты — [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `refactor:`, `test:`); ветки `feature/<имя>` → PR в `main` (даже соло — привычка + история для портфолио).
- Не тащить библиотеку, пока не нужна. Не начинать следующий этап, пока текущий не «Готово, когда».
- Все версии библиотек — актуальные на момент подключения (проверять в Android Studio / Maven Central), в доках версии намеренно не зафиксированы.
